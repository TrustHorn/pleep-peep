# pleep-peep — Техническое задание проекта

- **Название проекта:** pleep-peep
- **Тема:** Интеллектуальная платформа анализа алгоритмических закономерностей TikTok и Instagram с использованием искусственного интеллекта
- **Тип проекта:** Веб-платформа для аналитики социальных сетей и AI-генерации контента
- **Команда разработки:** Медет, Аманкос, Олжас
- **Репозиторий:** `pleep-peep`
- **Статус:** Разработка технического задания и проектирование
- **Формат:** Учебный командный веб-проект с возможностью дальнейшего коммерческого развития

---

## 1. Описание и основная идея проекта

**pleep-peep** — интеллектуальная веб-платформа, предназначенная для исследования видеоконтента, анализа конкурентов, комментариев аудитории, популярных хештегов и выявления закономерностей распространения контента в социальных сетях TikTok и Instagram.

Главная идея проекта заключается в создании единой системы, которая позволит пользователям не просто просматривать статистику чужих публикаций, а получать полноценные аналитические рекомендации по созданию собственного контента на основе обнаруженных тенденций.

Система объединяет аналитические инструменты, обработку данных и технологии искусственного интеллекта для решения задач контент-маркетинга.

Вместо ручного просмотра сотен видеороликов пользователь сможет указать интересующую его нишу, добавить конкурентов, выбрать хештеги и получить структурированный анализ публикаций, комментариев и востребованных форматов.

На основании результатов анализа искусственный интеллект будет формировать рекомендации, сценарии видеороликов, предложения по новым публикациям и итоговое аналитическое заключение — **AI Summary**.

### 1.1. Основная цель

Разработать веб-платформу, способную автоматизировать доступные этапы конкурентного анализа TikTok и Instagram и помогать пользователям принимать обоснованные решения о создании новых видеоматериалов.

### 1.2. Основные задачи

1. Анализировать доступные показатели видеороликов конкурентов.
2. Определять форматы публикаций, демонстрирующие высокую вовлечённость.
3. Исследовать комментарии, вопросы и предпочтения аудитории.
4. Анализировать хештеги и их связь с тематикой публикаций.
5. Выявлять повторяющиеся характеристики успешного контента.
6. Формировать рекомендации по дальнейшей контент-стратегии.
7. Генерировать оригинальные идеи, сценарии и видеоматериалы по заданным темам и хештегам.
8. Предоставлять итоговые AI-отчёты с выводами и обоснованиями.
9. Организовать совместную работу клиентов и специалистов внутри платформы.
10. Обеспечить разграничение доступа к рабочим пространствам и аналитическим материалам.

### 1.3. Важное ограничение

Внутренние алгоритмы рекомендаций TikTok и Instagram являются закрытыми. pleep-peep не предполагает прямого доступа к их исходному коду или внутренним моделям ранжирования.

Под анализом алгоритмов в данном проекте понимается **исследование наблюдаемых закономерностей** на основании доступных метрик, характеристик публикаций и поведения аудитории.

Результаты анализа носят вероятностный характер. Система не гарантирует определённое количество просмотров или попадание ролика в рекомендации.

## 2. Актуальность и решаемая проблема

Продвижение в социальных сетях требует постоянного исследования конкурентов, наблюдения за трендами, изучения аудитории и регулярного создания новых публикаций.

При традиционном подходе значительная часть этой работы выполняется вручную.

Контент-менеджеры и маркетологи самостоятельно собирают информацию о конкурентах, просматривают видеоролики, читают комментарии, записывают показатели и пытаются определить причины популярности отдельных публикаций.

Такой процесс занимает много времени, а полученные выводы нередко остаются субъективными.

**pleep-peep** предназначен для частичной автоматизации этих процессов.

### 2.1. Проблемы и предлагаемые решения

| Проблема | Предлагаемое решение pleep-peep |
|---|---|
| Необходимость вручную просматривать большое количество роликов | Формирование каталога публикаций с автоматической обработкой доступных данных |
| Сложность определения эффективных форматов | Сравнение показателей и характеристик публикаций |
| Большой объём комментариев | AI-классификация комментариев по темам, тональности и вопросам |
| Отсутствие единого инструмента для исследования конкурентов | Сводная аналитическая панель |
| Сложность выбора хештегов | Тематический анализ и сравнение хештегов |
| Недостаток новых идей для публикаций | AI-генерация оригинальных концепций и сценариев |
| Большое время на подготовку видеоматериалов | Создание черновиков видеороликов по утверждённым сценариям |
| Необходимость вручную готовить отчёт | Автоматическое формирование AI Summary |
| Отсутствие структурированной командной работы | Роли, задания, согласования и история изменений |

## 4. Основные функциональные возможности

### 4.1. Анализ видеороликов конкурентов

Пользователь добавляет ссылки на интересующие аккаунты или видеоролики TikTok и Instagram.

Система проверяет доступность источников и, при наличии разрешённого способа получения данных, формирует набор публикаций для анализа.

Планируемые функции:

- Добавление конкурентных аккаунтов.
- Создание списка конкурентов по отдельным проектам.
- Просмотр доступных публикаций конкурентов.
- Сравнение роликов за выбранный период.
- Сортировка по просмотрам, лайкам, комментариям и вовлечённости.
- Анализ длительности и частоты публикаций.
- Определение распространённых тем и форматов.
- Сравнение динамики показателей при наличии исторических данных.
- Формирование аналитических выводов.

### 4.2. Анализ метрик публикаций

| Метрика | Описание | Назначение |
|---|---|---|
| Просмотры | Количество просмотров видео, если показатель доступен | Оценка охвата публикации |
| Лайки | Количество отметок «Нравится» | Оценка положительной реакции |
| Комментарии | Количество комментариев | Оценка активности аудитории |
| Репосты | Количество распространений видео | Изучение потенциала распространения |
| Сохранения | Количество сохранений, если доступно | Оценка практической ценности |
| Engagement Rate | Отношение взаимодействий к выбранной базе расчёта | Сравнение вовлечённости |
| Длительность | Продолжительность видеоролика | Исследование эффективных форматов |
| Дата публикации | Время размещения видеоролика | Анализ частоты и расписания |
| Хештеги | Метки, использованные автором | Анализ тематической принадлежности |
| Тематика | Определяемая категория контента | Группировка публикаций |

**Важно:** все метрики отображаются только при наличии соответствующих исходных данных. Недоступные значения не подменяются предположениями.

Для Engagement Rate система должна явно указывать формулу и базу расчёта, например по просмотрам или по подписчикам, чтобы показатели не сравнивались некорректно.

### 4.3. AI-анализ комментариев

Модуль предназначен для интеллектуальной обработки комментариев под исследуемыми видеороликами.

Основные возможности:

1. Загрузка разрешённых к обработке комментариев.
2. Определение языка текста.
3. Анализ положительных, отрицательных и нейтральных реакций.
4. Группировка повторяющихся вопросов.
5. Выявление пожеланий и проблем аудитории.
6. Определение часто обсуждаемых тем.
7. Формирование краткого содержания больших массивов комментариев.
8. Подготовка рекомендаций для новых публикаций.

**Пример результата:**

| Категория комментариев | Пример содержания | Возможное действие |
|---|---|---|
| Вопросы о товаре | Пользователи спрашивают о характеристиках | Создать видео с ответами |
| Вопросы о цене | Аудитория интересуется стоимостью | Подготовить обзор цен |
| Положительные отзывы | Зрители выделяют полезные свойства | Использовать тему в следующих публикациях |
| Критика | Пользователи указывают на недостатки | Подготовить объективное сравнение |
| Запросы на продолжение | Зрители просят вторую часть | Разработать продолжение ролика |

AI должен отделять мнение аудитории от проверенного факта, а при недостаточном количестве комментариев сообщать об ограниченной достоверности анализа.

### 4.4. Анализ хештегов

Пользователь вводит один или несколько хештегов, связанных с интересующей его тематикой.

Платформа анализирует доступные публикации и определяет повторяющиеся тенденции.

Планируемые функции:

- Поиск и группировка публикаций по хештегам.
- Анализ популярности наблюдаемых публикаций.
- Сравнение связанных тематик.
- Выявление часто используемых сочетаний хештегов.
- Определение соответствия хештегов выбранной нише.
- Генерация предложений для новых публикаций.
- Сохранение наборов хештегов в проекте.

Рекомендации формируются на основе доступной выборки, а не предполагаемого знания внутреннего механизма продвижения платформ.

### 4.5. AI-генерация идей и сценариев

После обработки исходных данных пользователь переходит к созданию контента.

AI использует результаты анализа конкурентов, комментариев, тематики и хештегов.

Результат включает:

- Название будущего видеоролика.
- Основную идею.
- Целевую аудиторию.
- Рекомендуемую длительность.
- Сценарий видеоролика.
- Первые секунды видео — привлекающее внимание вступление.
- Последовательность сцен.
- Текст для озвучивания.
- Предложения по визуальному оформлению.
- Описание публикации.
- Подходящие хештеги.
- Призыв к действию при необходимости.

Генерируемые сценарии должны быть оригинальными и не предполагать дословного копирования материалов конкурентов.

### 4.6. Создание новых видеороликов

Одна из планируемых возможностей pleep-peep — подготовка новых видео на основе выбранной тематики, хештегов и результатов анализа.

Система предлагает следующий процесс:

1. Пользователь выбирает тему или набор хештегов.
2. AI формирует несколько концепций.
3. Пользователь выбирает подходящую идею.
4. Система генерирует сценарий и раскадровку.
5. Пользователь подтверждает сценарий.
6. На основе предоставленных или лицензированных материалов создаётся видеочерновик.
7. Пользователь просматривает и редактирует результат.
8. Утверждённый видеоролик становится доступен для экспорта.

Дополнительно в дальнейшем может быть реализована генерация отдельных видеосцен средствами text-to-video или image-to-video.

Для первой версии предусматривается базовый сценарий создания видеочерновиков из разрешённых материалов, текста, титров и шаблонов.

Автоматическая публикация в TikTok или Instagram не является обязательной функцией первой версии.

### 4.7. Итоговый AI Summary

**AI Summary** — итоговый отчёт, объединяющий результаты проведённого исследования.

Отчёт должен формироваться по завершении анализа и содержать:

1. Цель и параметры исследования.
2. Использованные платформы и период анализа.
3. Количество обработанных публикаций и комментариев.
4. Основные характеристики успешных роликов.
5. Выявленные закономерности.
6. Основные темы обсуждений аудитории.
7. Анализ применяемых хештегов.
8. Сравнение выбранных конкурентов.
9. Рекомендации по созданию новых видеороликов.
10. Предлагаемые темы и сценарии.
11. Итоговые выводы и дальнейшие действия.
12. Ограничения данных и степень обоснованности рекомендаций.

Пользователь должен иметь возможность просмотреть отчёт и экспортировать его в удобном формате.

Для ключевых выводов необходимо сохранять ссылки на исходные публикации или агрегированные данные, на основании которых они сформированы.

## 6. Роли и обязанности разработчиков

Разработка pleep-peep выполняется командой из трёх участников.

Предлагаемое распределение ответственности:

| Участник | Основная роль | Обязанности | Ожидаемый результат |

## 7. Взаимодействие клиентов и разработчиков

Взаимодействие между сторонами является отдельной частью организации проекта pleep-peep.

### 7.1. Принцип работы

**Клиент отвечает за постановку задачи, выбор источников и утверждение результата. Разработчик отвечает за техническую реализацию, исправность функций и устранение ошибок.**

Клиент не должен иметь прямой доступ к исходному коду, базе данных или технической инфраструктуре.

Разработчики не должны изменять клиентские отчёты или пользоваться конфиденциальными данными без необходимых полномочий.

### 7.2. Таблица взаимодействий

| Аналитика | Изучает показатели и выбирает параметры | Обеспечивает корректность обработки | Аналитический результат |
| Генерация идей | Выбирает темы и характеристики видео | Поддерживает AI-модуль | Подготовленные концепции |

### 7.3. Система обращений

Для коммуникации предусматривается модуль **Support & Feedback**.

Клиент сможет создавать обращения следующих типов:

- Техническая ошибка.
- Некорректные аналитические данные.
- Ошибка генерации контента.
- Проблема с доступом.
- Запрос новой функции.
- Консультация.

Каждому обращению присваивается статус.

| Статус | Значение |
|---|---|
| Новое | Обращение зарегистрировано |
| На рассмотрении | Ответственный изучает запрос |
| Требует уточнения | Необходимо дополнительное описание |
| В работе | Разработчик выполняет задачу |
| На проверке | Результат передан для проверки |
| Выполнено | Решение принято и подтверждено |
| Закрыто | Работа по обращению завершена |

### 7.4. Сценарий согласования видеоролика

1. Клиент запускает исследование.
2. AI предлагает темы и идеи.
3. Клиент выбирает концепцию.
4. Контент-креатор формирует сценарий.
5. Владелец проекта проверяет сценарий.
6. После утверждения создаётся видеочерновик.
7. Клиент просматривает видеоролик.
8. При необходимости возвращает его на исправление.
9. Утверждённое видео отправляется в библиотеку готовых материалов.
10. Результаты отражаются в истории проекта и итоговом отчёте.

### 7.5. Статусы контента

**Черновик → На согласовании → Одобрен → В генерации → Готов к проверке → Утверждён → Архивирован.**

Если материал отклонён, он возвращается на доработку с указанием причины.

## 10. Источники данных и ограничения платформ

Для аналитики предполагается использовать официальные API, разрешённые интеграции, лицензированные наборы данных или материалы, предоставленные клиентом на законных основаниях.

### 10.1. TikTok

Возможности сбора данных зависят от типа разрешённого API-доступа и условий TikTok.

Research API предназначен для одобренных исследовательских проектов и не является универсальным коммерческим инструментом анализа конкурентов.

Поэтому работа pleep-peep не должна зависеть исключительно от получения такого доступа.

Допускается создание демонстрационного аналитического модуля на тестовых данных и дальнейшее подключение подходящего легального источника.

### 10.2. Instagram

Доступные возможности Instagram API зависят от типа аккаунта, разрешений приложения и одобренных функций.

Получение данных о публикациях, хештегах, комментариях и конкурентных аккаунтах может быть ограничено.

Функции, для которых отсутствует разрешённый доступ, не должны представляться пользователю как работающие в полном объёме.

### 10.3. Общие ограничения

- Запрещается предполагать наличие полного доступа ко всем публичным и закрытым данным.
- Не допускается обход технических ограничений и механизмов авторизации.
- Персональные данные должны обрабатываться только при наличии правового основания.
- Использование чужих видеоматериалов для генерации нового контента требует соответствующих прав.
- Отсутствующие метрики не должны генерироваться искусственным интеллектом как реальные значения.
- Аналитика должна показывать размер выборки, период и ограничения источника.

## 12. Основные пользовательские сценарии

### Сценарий №1. Анализ конкурентов

**Участник:** SMM-специалист.

1. Авторизуется в системе.
2. Выбирает рабочий проект.
3. Добавляет несколько аккаунтов конкурентов.
4. Выбирает TikTok или Instagram.
5. Устанавливает период исследования.
6. Запускает анализ доступных публикаций.
7. Получает сравнительную таблицу.
8. Изучает наиболее успешные ролики.
9. Формирует AI Summary.
10. Сохраняет рекомендации.

**Ожидаемый результат:** структурированная аналитика конкурентов с рекомендациями для собственной контент-стратегии.

### Сценарий №2. Исследование комментариев

**Участник:** аналитик клиента.

1. Выбирает ранее исследованные видеоролики.
2. Запускает анализ доступных комментариев.
3. Система классифицирует сообщения по тематике.
4. AI выделяет повторяющиеся вопросы.
5. Аналитик изучает результат.
6. Выбирает темы, интересующие аудиторию.
7. Передаёт рекомендации SMM-специалисту.

**Ожидаемый результат:** список потребностей аудитории и предложений по новым видеоматериалам.

### Сценарий №3. Создание контента по хештегам

**Участник:** контент-креатор.

1. Получает утверждённую аналитическую задачу.
2. Выбирает хештеги.
3. Указывает целевую аудиторию.
4. Запрашивает генерацию идей.
5. AI предлагает несколько концепций.
6. Контент-креатор выбирает одну концепцию.
7. Генерирует сценарий и раскадровку.
8. Передаёт сценарий владельцу проекта.
9. После утверждения создаёт видеочерновик.
10. Вносит правки и отправляет материал на финальную проверку.

**Ожидаемый результат:** оригинальный видеоролик, подготовленный на основе результатов исследования.

### Сценарий №4. Итоговый AI-отчёт

**Участник:** владелец проекта.

1. Открывает завершённое исследование.
2. Проверяет использованные источники.
3. Просматривает статистику и основные выводы.
4. Запускает формирование AI Summary.
5. Изучает рекомендации.
6. Определяет дальнейшие задачи для команды.
7. Сохраняет или экспортирует отчёт.

**Ожидаемый результат:** документированный набор выводов и рекомендаций для следующих публикаций.

## 16. Ожидаемый результат проекта

В результате разработки pleep-peep предполагается получить интеллектуальную платформу, объединяющую исследование социальных сетей, анализ поведения аудитории и инструменты AI-генерации контента.

Пользователи смогут исследовать доступные публикации конкурентов, изучать комментарии, сравнивать показатели, определять интересные аудитории темы и формировать собственные видеоматериалы.

Использование искусственного интеллекта позволит сократить объём ручной аналитической работы и преобразовывать исходные данные в понятные рекомендации.

Дополнительным результатом станет организация командного взаимодействия между владельцами проектов, SMM-специалистами, аналитиками и создателями контента.

Разработчики будут отвечать за техническую реализацию, поддержку архитектуры, корректную обработку данных и функционирование системы.

### 16.1. Пример итогового процесса

**Исходные данные клиента:**

- Тематика: продажа электроники.
- Платформы: TikTok и Instagram.
- Конкуренты: три выбранных аккаунта.
- Период исследования: последние 30 дней.
- Хештеги: тематические метки электроники и обзоров.

**Планируемые результаты системы:**

| Этап | Результат |
|---|---|
| Анализ конкурентов | Сравнительная таблица доступных метрик |
| Анализ видео | Список роликов с наиболее высокой вовлечённостью |
| Анализ комментариев | Популярные вопросы и интересы аудитории |
| Анализ хештегов | Подходящие тематические сочетания |
| AI Recommendations | Предложения по форматам будущих публикаций |
| AI Content Studio | Несколько оригинальных сценариев |
| Video Studio | Черновик нового видеоролика |
| AI Summary | Итоговый отчёт с рекомендациями и ограничениями анализа |

### 16.2. Итоговая концепция

**pleep-peep — это не просто сервис просмотра статистики TikTok и Instagram, а комплексная система принятия решений для создания видеоконтента на основе данных и искусственного интеллекта.**

Основной принцип проекта:

**Анализ конкурентов → Исследование аудитории → Выявление тенденций → Генерация идей → Создание видео → Согласование → AI Summary.**
